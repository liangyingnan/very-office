# 修复打开文档注入后不重排（空白直到用户输入）

- 时间：2026-08-10
- 项目路径：`F:\JsWorkSpace\very-office`

## 背景/问题

打开本地 docx 后页面显示空白文档，**敲任意字符后全部内容才出现**。
（同日早些时候修的"按需字体加载"把打开从 ~18s 提速到 ~1.5s，但用户反馈该症状仍在——
说明它不是速度慢，而是**注入后编辑器根本不做初始重排**。）

## 复现与定位（Playwright 探针）

1. 截图复现：注入完成后逻辑文档 `GetText()` 已有全部内容，但 canvas 上无文字；
   模拟按键后文字出现。
2. 状态探针：注入后 `m_oLogicDocument.Pages.length === 0`（排版页数为 0，从未重排）。
3. 链路探针（包装 `asyncFontsDocumentEndLoaded` / `RecalculateFromStart` 等）：
   - 首次（空文档）打开：`asyncFontsDocumentEndLoaded` 内部触发 `CDocument.RecalculateFromStart` ×2 → 正常排版。
   - 二次（真实字节注入）打开：`asyncFontsDocumentEndLoaded` 直接返回，**无任何重排**。

## 根因

`word/sdk-all-min.js` `asc_docs_api.prototype._openDocumentEndCallback`（78271 行）开头 guard：

```js
if (this.isDocumentLoadComplete || !this.ServerImagesWaitComplete || !this.ServerIdWaitComplete || ...) return;
```

离线流程"先开空文档、后注入真实字节"在同一 api 实例二次 openDocument。首开完成后
`onDocumentContentReady` 把 `isDocumentLoadComplete` 置为 true（59020 行）；二次打开时
没有任何环节复位它（正常重开走 `asc_CloseFile` 复位，离线注入不走该路径），导致
`_openDocumentEndCallback` 直接 return —— 不执行 `RecalculateFromStart()`（78353）、
不发 `asc_onDocumentContentReady`、不 `GenerateStyles()`。用户输入触发局部重排，内容才显现。

## 修复

`tools/inject-9.4.0-offline-shim.py` 的 `HISTORY_RESET_SHIM`（包装
`baseEditorsApi.prototype.asc_openDocumentFromBytes`，离线注入共用入口）在原有 History 重置之外
增加一行 `this.isDocumentLoadComplete = false;`，让二次打开走完整的 finalize 链路。

- 新标记 `__ooReopenRecalcPatched`；注入脚本对旧版 history shim 自动删尾部 IIFE 重注（幂等）。
- 已对 word/cell/slide/visio 重跑注入（标记各 1 份），`.br`/`.gz` 已重建。
- Service Worker 缓存版本 `_v11` → `_v12`。

`ServerImagesWaitComplete` 在 `asyncImagesDocumentEndLoaded` 里调用前已置 true（78209），
`ServerIdWaitComplete` 首开后保持 true，均无需处理。

## 验证

- 注入后 +5s：`Pages=1`、`IsFreezePage(0)=false`（之前恒 0/true）。
- 截图确认：**不输入任何字符内容即渲染**。
- 回归 `test-save-reopen` / `test-insert-text` / `test-bin-insert` / `test-open-edit-save` 全部 PASS，
  downloadas 0 次，无 pageerror。

## 注意

- 该 guard 在 cell/slide/visio 的 `_openDocumentEndCallback` 同样存在（baseEditorsApi 层），
  shim 包装在 baseEditorsApi.prototype 上，四产品同享修复。
- 副作用可接受：`asc_onDocumentContentReady` 会再发一次（web-apps 幂等处理），
  `_autoSave` 的 40ms interval 会多挂一个（上游 `asc_CloseFile` 重开路径同样如此）。
