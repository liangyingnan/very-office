# 修复 9.4.0 编辑器加载卡死、-18 连接失败及离线打开/保存全链路打通记录

**时间**: 2026-07-30 ~ 2026-07-31
**项目路径**:
- `F:\JsWorkSpace\onlyoffice-ai-word-demo` (React + Electron 宿主应用)
- `F:\JsWorkSpace\OnlyofficePersonal` (ONLYOFFICE 9.4.0 脱机资源项目)

## 背景问题

在《修复9.4.0前端卡住及集成原生AI插件全过程.md》记录的工作之后，demo 启动后仍**永远停在"正在加载编辑器，首次需编译 WASM，请稍候…"遮罩层**，调试日志框全黑无任何输出。修复卡死后又暴露出第二层级问题：编辑器报 **-18 "连接失败。您仍然可以查看文档，但在连接恢复之前无法下载或打印"**，且 socket.io 对 `/9.4.0/vendor/doc/<key>/c/` 无限 404 轮询，文档无法进入编辑态。用户同时提出疑问：为什么 9.3.0.136 可以"正常连接"。

## 一、9.4.0 资源检查：发现实现并不正确

### 1. 卡死根因：word/sdk-all-min.js 是 0 字节文件

- 全目录扫描 9.4.0 下所有 `.js/.wasm/.json`，唯一的 0 字节文件是 `9.4.0/vendor/sdkjs/word/sdk-all-min.js`（7-30 16:32 被截断）。
- 编辑器加载链为 `api.js → index_loader.html → index.html → app.js`，`app.js` 中 requirejs 配置 `sdk: '../../sdkjs/word/sdk-all-min'`。加载到空文件后内核静默不初始化 → 不触发 `onDocumentReady` → 宿主收不到 `onlyoffice-document-ready` → 遮罩层永久停留，且**不产生任何报错日志**（与空白日志框现象吻合）。
- 成因：`tools/uninject-offline.py` 在清洗 9.3.0 脱机补丁时重写四个 app 的 `sdk-all-min.js`，word 被意外写空；cell/slide/visio 虽可解析但与构建原件不一致（各少约 87KB）。
- 注意：`node --check` 对空文件会误判通过（空程序合法），不能作为唯一校验手段。

### 2. 恢复方式

- 在 `build-tmp/sdkjs/deploy/sdkjs/` 中找到同一次构建的**原始产物**（其 `sdk-all.js` 与 vendor 内字节一致，确认同源性）。
- 用原件逐字节恢复 word/cell/slide/visio 四个 `sdk-all-min.js`，并重建全部 `.br/.gz` 压缩产物。
- 教训：曾尝试用未压缩的 `sdk-all.js` 直接冒充 `sdk-all-min.js`，**不可行**——官方 min 构建额外拼入了 `commonDefines.js`（含 `var lcid_enUS = 0x0409;` 等全局定义），裸 `sdk-all.js` 缺这些定义会抛 `lcid_enUS is not defined`。

### 3. 与记录文档不符之处

- 前次记录称"在 `OnlyofficeEditor.tsx` 的 `buildDocConfig` 中加入十款插件的 pluginsData"，实际该配置写在了 `OnlyofficePersonal/assets/office-config.js`（供 `office.html` 使用），demo 的配置里并没有。本次已补齐到 demo。

## 二、9.3.0 为什么"正常" vs 9.4.0 的 -18 连接失败

- 9.3.0.136 的 `sdk-all-min.js` 内仍保留着旧的脱机补丁（`_downloadAsFromLocal` 等 2 处），它 stub 掉了协同握手与下载链路，所以**根本不连 socket**，用户感知为"正常"。
- 9.4.0 恢复纯净后，按 URL 加载文档会走真实的协同握手：socket.io 连接 `/doc/<key>/c/`（404）→ 重试 15 次 → 触发 `CoAuthoringDisconnect(-18)` 弹窗，且 `setViewModeDisconnect` **强制切换为只读**，文档甚至不会下载。

**结论：9.4.0 离线运行必须绕开协同握手。9.4.0 sdk 自带原生离线模式（OfflineApp），但存在一连串隐藏机关，本次逐一打通。**

## 三、9.4.0 原生离线模式的打通（核心工作）

### 1. 开关：`document.url = '_offline_'`

- sdk 内 `AscCommon.offlineMode = '_offline_'`；当 `documentUrl === '_offline_'` 时 `DocInfo.put_OfflineApp(true)`。
- OfflineApp 下 `_coAuthoringInit` 不再 `set_url(null)`，`DocsCoApi._url` 保持 `""` → `isRightURL()` 为 false → `CDocsCoApi.init` 走 **dummy 分支**（`onFirstConnect() + onLicense(null)`），**完全不创建 socket**。实测 socket 请求从无限轮询降为 0 次。
- 落地：`onlyoffice.html` 的 `loadOnlyoffice` 在 `config.localOpenFromBinary` 时把 `document.url/directUrl` 改写为 `'_offline_'`。

### 2. 机关一：`AscCommon.getEmpty` 缺失

- OfflineApp 启动时 `_openEmptyDocument` 调用 `AscCommon.getEmpty()` 取空文档 SER bin；word 构建未导出它（只有 cell 构建自带），抛 `getEmpty is not a function`。
- 但 word 的 `sdk-all.js` 里有现成的死变量 `g_sEmpty_bin = "DOCY;v4;8985;..."`（空文档 blob）。
- 坑：`checkStreamSignature` 按**字节**比较（`stream[i] !== Signature.charCodeAt(i)`），返回字符串会判 false 进而走到不存在的 legacy `OpenDocument` 路径。shim 必须把 blob 转成 `Uint8Array` 返回。

### 3. 机关二：许可与版本守卫

- dummy `onLicense(null)` 使 `licenseResult = null`，而 `asc_CAscEditorPermissions` 默认 `licenseType = Error` → `Main.js onEditorPermissions` 弹"许可过期"并**中断文档加载**。
- `Main.js onServerVersion` 在 `window.compareVersions` 缺失且版本号不匹配时弹"服务器版本过旧"并中断。
- shim 处置：`window.compareVersions = true`；包装 `baseEditorsApi.prototype._onEndPermissions`，在 `licenseResult === null` 时补一份本地许可 `{type: 3(Success), rights: 1(Edit), buildVersion: '9.4.0', ...}`。

### 4. 机关三：本构建没有 ooxml 浏览器端读写模块

- 起初尝试 `openDocument({buffer: docxBytes})` 直开 docx：`openDocument` 的 `OpenDocumentFromZip` 分支要求 `Asc.Addons.ooxml = true`（iframe 内补设后），又抛 `m_oLogicDocument.fromZip is not a function`——zip 读取器根本没编进这个构建（`saveDocumentToZip` 写入器同样缺失，`onSaveDocument` 保存链因此也不可用）。
- **打开**改走：`x2t.wasm` 客户端转换。`x2t_helper.js`（项目已改造过，含 `downloadFile` 文件流劫持）提供 `convertToBin(docx → SER bin)`，再以 `docEditor.openDocument({buffer: serBin})` 注入，`checkStreamSignature('DOCY')` 通过 → `OpenDocumentFromBin`（BinaryFileReader，本构建可用）。
- **保存**改走：编辑器内核 `Asc.editor.asc_nativeGetFile3()`（返回 `{header, data}`，即当前文档 SER bin）→ 拼接为带 DOCY 签名的完整 Editor.bin → `x2t_helper` 的 `convertFromBin` 本地转为 docx/pdf，字节直接 postMessage 回宿主，全程零服务器。

### 5. 机关四：openResult 竞态

- OfflineApp 启动自动开空文档，与随后注入真实字节的两条打开链会竞争 `this.openResult`（后到的 `onEndLoadFile` 覆盖先到的）。
- 处置：真实字节推迟到**首次 `onDocumentReady`（空文档就绪）之后**再注入。

### 6. 机关五：编辑器 iframe 选择器

- 9.4.0 的 api.js 用 `replaceChild(iframe, target)` 把 `#editor` 占位 div 替换掉，`#editor iframe` 永远匹配不到。统一改用 `iframe[name="frameEditor"]`（兼容回退 `#editor iframe`）。`setStreamOnlyFlag` 等旧代码同样受益。

### 7. 机关六：跨 realm 字节与注入状态

- `x2t_helper` 的类型判断是 `instanceof`，宿主 realm 创建的 `ArrayBuffer/Uint8Array` 在 iframe 内全判为 `'object'` 被拒。所有交给 x2t 的字节一律用 **iframe realm 的构造器**（`new w.Uint8Array(...)`）重建；`postMessage` transfer 前用 `ArrayBuffer.isView`（跨 realm 有效）归一化。
- x2t 注入状态（`x2tInjectPromise`）按 **iframe window 记忆**，并在 `loadOnlyoffice` 重建编辑器（`destroyEditor` 后 iframe 是全新 window）时重置——否则第二次打开文档会报 `Cannot read properties of undefined (reading 'convertToBin')`。
- `x2t_helper.js` 注入 src 必须用根路径 `/9.4.0/...`（相对路径会拼到 `documenteditor/main/` 下 404）；其内部 `x2t.js/x2t.wasm` 由 emscripten 按 `document.currentScript.src` 解析，链路自洽。

### 8. shim 固化

以上 2、3 两项（getEmpty、compareVersions、许可包装）已固化为可复现脚本：

```
python tools/inject-9.4.0-offline-shim.py [base_dir]
```

- 幂等（检测 `__ooOfflineLicensePatched` marker），从 `sdk-all.js` 现场提取 `g_sEmpty_bin`。
- 最终 `word/sdk-all-min.js` = 构建原件 + 12.8KB shim，`.br/.gz` 已同步重建。
- 与 9.3.0 的 `inject-offline.py` 本质区别：全部为 9.4.0 兼容的**增量**内容，不改写、不重排任何原始代码。
