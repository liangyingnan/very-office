# 修复打开文档长时间空白（按需字体加载）

- 时间：2026-08-10
- 项目路径：`F:\JsWorkSpace\very-office`

## 背景/问题

用户报告：打开本地 docx（bidder.docx，279 页）后页面长时间显示**空白文档**，
直到用户随便敲了一个字，真实内容才"突然"显示出来。

## 排查过程（Playwright 探针时间轴）

冷启动（全新浏览器 profile，`python -m http.server 8000`）细分计时：

| 时刻 | 事件 |
|------|------|
| ~13s | 编辑器 boot 完成、空文档 ready |
| 14.9s | `convertToBin` 开始（真实字节注入流程） |
| 31.5s | `convertToBin` 结束 → 注入完成、内容显示 |

结论先行：**不是"输入触发显示"，而是注入本来就慢 ~17s，用户敲字时恰好注入完成**
（敲入的字符会被 openDocument 重建冲掉）。

进一步包装 `x2t_helper.js` 内部函数计时：

- `fetchFonts`：**16.0s，抓取 273 个字体文件共 408MB**（`AscCommon.fetchFonts` shim 全量拉取
  `g_font_loader.fontInfos` 里 193 个字体的全部字重）
- `executeConversion`（wasm 本体）：**0.0s** —— 转换本身完全不慢

## 根因

离线 shim `AscCommon.fetchFonts`（`tools/inject-9.4.0-offline-shim.py` 注入）在每次 x2t 转换前
把**全部**字体 XHR 拉下来喂给 wasm MEMFS。全量 408MB 导致首次打开文档卡顿十几秒
（非 localhost 环境会更糟），且每次保存都往 MEMFS 重写 408MB。

## 修复（按需字体加载）

验证过的两个前提：

1. `g_font_loader.fontInfos` 的 193 个字体名**中英双语并存**（`宋体`/`SimSun`、`等线`/`DengXian`
   都是独立条目）→ 用 docx fontTable 里的名字精确匹配即可，无需别名表。
2. **bin→docx 保存完全不喂字体，产物仍合法**（zip 完整、fontTable 正常、内容无丢失）——
   字体文件只在「OOXML→SER bin（打开，算排版度量）」和「PDF 输入/输出（渲染字形）」时才需要。

改动：

- `../9.4.0.131/vendor/sdkjs/common/wasm/x2t/x2t_helper.js`
  - 新增 `extractUsedFonts(bytes, fileExt)`：内置迷你 zip 读取器（EOCD→中央目录→
    `DecompressionStream('deflate-raw')` 解压），从 docx（fontTable/styles/document/theme）、
    xlsx（styles/theme）、pptx（theme/slides/masters/layouts 的 `typeface=`）解析文档实际引用字体，
    并集常用兜底集（Calibri/Cambria/Arial/Times New Roman/宋体/等线/微软雅黑 等 17 个）。
  - `_convertDocument` 字体加载改为条件分支：`targetExt==='.bin'`（打开）→ 按需过滤，
    解析失败降级全量；PDF 输入/输出 → 全量；**其余文本类输出（bin→docx/xlsx/pptx/odf/txt…）完全跳过**。
  - `fetchFonts(fontNames)` 把过滤名单透传给 shim。
- `tools/inject-9.4.0-offline-shim.py`：`FETCH_FONTS_SHIM` 的 `AscCommon.fetchFonts(cb, filter)`
  支持第二参数字体名数组（小写集合匹配 `info.Name`）；检测标记升级为 `__ooFetchFontsFilter`
  （重跑脚本自动替换旧 shim，注意替换会把排在其后的 license/history shim 一并重注，属预期）。
- 已对 word/cell/slide/visio 四产品重跑注入脚本（幂等），各 shim 标记均为 1 份，
  `.br`/`.gz` 压缩产物已重建。
- Service Worker 缓存版本 `_v10` → `_v11`（`../9.4.0.131/vendor/document_editor_service_worker.js` 两处）。

## 效果（冷启动实测）

- 打开 docx：fetchFonts 273 文件/408MB/16s → **20 文件/28MB/1.3s**；
  空文档 ready → 内容显示 由 ~18s 缩到 **~1.5s**。
- 保存（bin→docx）：跳过字体加载，MEMFS 不再每次重写 408MB（内存占用同步下降）。
- PDF 导出路径保持全量字体，行为不变。
