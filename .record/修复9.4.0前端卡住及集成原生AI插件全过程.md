# 修复 ONLYOFFICE 9.4.0 启动白屏及原生 AI 插件集成全过程记录

**时间**: 2026-07-30
**项目路径**: 
- `F:\JsWorkSpace\onlyoffice-ai-word-demo` (React + Electron 宿主应用)
- `F:\JsWorkSpace\OnlyofficePersonal` (ONLYOFFICE 9.4.0 脱机资源项目)
- `F:\JsWorkSpace\DocumentServer` (ONLYOFFICE 官方核心服务端及前端源码仓库)
- `F:\JsWorkSpace\onlyoffice.github.io` (ONLYOFFICE 官方扩展与插件仓库)

## 背景问题
用户要求在 `onlyoffice-ai-word-demo` 项目中，去除其自带的外部 React AI 功能（包括聊天侧边栏、快捷漂浮按钮等），并转而启用 ONLYOFFICE 9.4.0 内置的强大原生 AI 插件及其他扩展插件（如 drawio、ocr 等）。

在移除外部 React 组件并在 `office-config.js` 配置插件后，用户反映遇到了严重的卡死问题，现象为编辑器永远停留在“正在加载编辑器，首次需编译 WASM，请稍候...”的遮罩界面，无法进入文档。

## 一、基于官方源码库的 9.4.0 资源提取与架构底座搭建

在排查卡顿之前，我们首先进行了一项至关重要的基础架构工作：从官方源码仓库中直接剥离和组装 9.4.0 的完整纯静态脱机运行环境。此项工作严重依赖于以下两个官方核心项目：

### 1. `DocumentServer` 核心引擎的抽取
脱机版的核心并非凭空产生，而是直接从 `F:\JsWorkSpace\DocumentServer` 项目中提取构建而来。
- 我们将该项目中的最新 `sdkjs` (核心渲染与逻辑交互层)、`web-apps` (编辑器前端 UI 与 API 层)、`dictionaries` (拼写检查依赖) 以及 `core-fonts` 等基础资源进行了重组，构建了纯静态的 9.4.0 离线包基座，完全摆脱了对服务端 Node.js 进程和 PostgreSQL 数据库的依赖，实现了在前端浏览器内的纯本地运行 (WASM)。

### 2. `onlyoffice.github.io` 官方插件库的集成
为了满足“拥有一个更全的离线版本”的需求，我们利用了 `F:\JsWorkSpace\onlyoffice.github.io` 项目。
- 从该项目的 `sdkjs-plugins` 目录中，我们原封不动地提取了 ONLYOFFICE 官方提供的海量优质插件源码（如 `ai`、`zhipu`、`drawio`、`ocr` 等数十个插件）。
- 将这些脱机插件包完整迁移至 `OnlyofficePersonal\9.4.0\sdkjs-plugins` 中，从而让本地编辑器即使在断网状态下也能原生地拥有原本需要连接云端扩展商店才能获得的强大能力。

## 二、9.4.0 版本核心功能完善与升级

在打好源码级的地基之后，我们进一步进行了以下核心脱机优化：

### 1. 静态资源深度优化与预压缩
为了提升离线环境下的首屏加载速度，我们在 `OnlyofficePersonal` 目录中升级了 `precompress.sh` 脚本：
- **资源覆盖面扩大**：针对庞大的 `.wasm` 引擎、JS 核心库，以及体积可观的字体文件（`vendor/fonts/`）和拼写检查字典（`vendor/dictionaries/`），全部纳入了预压缩范围。
- **高效压缩策略**：根据文件类型的不同，动态调整了 Brotli 压缩级别。对于体积高达数以百兆计的字体文件，采用了适中的压缩率以换取更快的构建速度，而对 `.js` 和 `.wasm` 则开启了极限压缩（级别 11）。这极大减轻了由于零拷贝挂载大体积脱机目录时的 I/O 负担，使编辑器资源能够被本地服务以 `.br` 和 `.gz` 的形式极速响应（如果配合 Nginx 等更高级的代理）。

### 2. 剥离外部宿主组件，回归原生生态
用户希望拥有一个“更全的离线版本”，要求去除非原生功能：
- **深度代码精简**：从 `onlyoffice-ai-word-demo` (React 侧) 彻底删除了原有的外挂式 AI 侧边栏 (`AiAgentSidebar.tsx`)、写作辅助面板 (`AiDocumentGen.tsx`)、自定义顶部助手条 (`AiRibbon.tsx`) 等侵入性组件。
- **通信通道瘦身**：清理了 `App.tsx` 和 `Navbar.tsx` 中与上述组件强绑定的状态钩子、配置文件加载逻辑以及相关的 `postMessage` 事件监听，将控制权完全交还给 ONLYOFFICE 核心引擎自身。

### 3. 全局插件环境打通
为了让 9.4.0 能够离线使用丰富的原生插件：
- **离线插件库映射**：在 `office-config.js` 中将编辑器默认配置的 `plugins` 进行了系统级配置，暴露了包括官方 AI、智谱 AI (Zhipu)、Draw.io、OCR 识别等在内的所有 `sdkjs-plugins` 资源。
- **无缝集成**：确保这些插件能够通过本地 Express 服务被正确拉取，实现在编辑器内点击顶部“插件”即可直接使用。

## 三、排查与修复前端加载白屏问题

### 1. 定位挂起原因（WASM 白屏）
最初怀疑是 `App.tsx` 中的通信机制被破坏，或者 `precompress.sh` 生成的 Brotli 压缩文件导致读取失败。在排查 `officeServer.ts` 源码后，发现 Express `static` 中间件的行为表现正常，并且 `OnlyofficeEditor.tsx` 中的事件通信并未发生致命破坏。

进一步排查发现，真正的罪魁祸首是**更早时期对核心 JS 进行的侵入式补丁**：
- 之前我们将为 9.3.0 编写的脱机保存补丁（`inject-offline.py`）强行执行并写入了 9.4.0 的 `sdk-all-min.js`。
- 9.4.0 的 `sdk-all-min.js` 中使用了 Webpack 等打包工具深度混淆了源码，并未像 9.3.0 那样在全局 `window` 对象上暴露 `window.AscCommon`。
- 补丁生成的 `OFFLINE_BLOCK` IIFE 闭包在执行时，因访问 `window.AscCommon.baseEditorsApi` 直接抛出了 `TypeError: Cannot read properties of undefined` 运行时语法错误。
- 这一严重异常直接导致 ONLYOFFICE JS 内核终止执行，`DocsAPI.DocEditor` 生命周期中断，进而再也无法通过 `postMessage` 向 React 宿主发送 `onlyoffice-document-ready` 指令，从而死锁在遮罩层。

### 2. 撤销错误注入（内核恢复）
编写并运行了 `uninject-offline.py`，遍历并清洗了 `word`、`cell`、`slide`、`visio` 四个应用目录下被污染的 `sdk-all-min.js`，移除了无法兼容的 9.3.0 脱机代码块和错误替换，将 ONLYOFFICE 9.4.0 恢复到了纯净的初始状态。

### 3. 清理浏览器缓存导致的“假死”
由于用户在 Electron 中测试，Chromium 内核对静态资源（特别是高达十余 MB 的 `sdk-all-min.js`）进行了激进的 Disk Cache，导致我们修复底层文件后，页面依然加载了携带报错崩溃逻辑的旧缓存。
为此，对本地 Express 服务器 (`officeServer.ts`) 进行了如下改造，强制绕过浏览器缓存：
```typescript
this.app.use((req, res, next) => {
    res.setHeader('Cache-Control', 'no-store, no-cache, must-revalidate, proxy-revalidate');
    res.setHeader('Pragma', 'no-cache');
    res.setHeader('Expires', '0');
    express.static(this.config.onlyofficeRoot)(req, res, next);
});
```

### 4. 开启 Electron 开发者模式 & 注入日志
为了彻底观测底层的运行情况：
- 在 `main.ts` 的 `createWindow` 中加入了 `mainWindow.webContents.openDevTools();` 强制弹出控制台。
- 修改了 `onlyoffice.html`，全局劫持了 `console.log`、`console.error` 和 `window.onerror`，将 iframe 内部的所有日志通过 `postMessage('onlyoffice-debug-log')` 同步到外层。
- 在 `OnlyofficeEditor.tsx` 中增加了日志接收和渲染视图，直接在加载遮罩层下方滚动呈现内部加载日志，帮助我们确认没有任何 404 或语法错误发生。

### 5. 整合原生 AI 及官方插件
在成功确保内核健康加载后，在 `OnlyofficeEditor.tsx` 中更新了编辑器的实例化配置 `buildDocConfig`。移除了外部的 AI Sidebar 后，正式通过官方配置方式启用了十款强大的离线插件：
```typescript
plugins: {
  pluginsData: [
    "9.4.0/sdkjs-plugins/content/ai/config.json",
    "9.4.0/sdkjs-plugins/content/zhipu/config.json",
    "9.4.0/sdkjs-plugins/content/drawio/config.json",
    "9.4.0/sdkjs-plugins/content/highlightcode/config.json",
    "9.4.0/sdkjs-plugins/content/ocr/config.json",
    "9.4.0/sdkjs-plugins/content/photoeditor/config.json",
    "9.4.0/sdkjs-plugins/content/translator/config.json",
    "9.4.0/sdkjs-plugins/content/zoom/config.json",
    "9.4.0/sdkjs-plugins/content/languagetool/config.json",
    "9.4.0/sdkjs-plugins/content/mathpix/config.json"
  ]

```

## 四、总结
本次修复核心在于清理了不兼容旧版本黑客补丁导致的严重底层运行时异常，并通过强制更新本地环境缓存，重新激活了 9.4.0 的完整功能。用户现在可以直接在 ONLYOFFICE 原生工具栏的“插件”选项卡中，体验到包括官方 AI 助手和各类丰富工具的完整离线生态。
