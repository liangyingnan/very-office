## x2t-wasm 编译踩坑（WSL+Docker 行尾问题）
- 在 Windows 下 `git checkout` onlyoffice-x2t-wasm 后，仓库内大量脚本被转成 CRLF（共 190 个：41 个 .sh + Dockerfile + 148 个带 shebang 的 .py/.awk/.pl/configure/gradlew 等）。
- 症状：`docker build` 报 `/usr/bin/embuild.sh: /usr/bin/bash^M: bad interpreter: No such file or directory`（exit 126）。容器内 Linux 只认 LF。
- 修复：用 Python 把全部 `.sh` 和所有「首行带 `#!` 且含 CR」的文件批量 `replace(b"\r\n",b"\n")`。Git Bash 的 `find -exec +` 会报 “environment too large for exec()”，别用，改用 Python 遍历。
- 永久修复建议：在 WSL 里 `git config core.autocrlf false` 后 `git rm --cached -r . && git reset --hard` 重新检出为 LF，避免 `git checkout` 又变回 CRLF。
- 当前 git status 会显示这些文件“modified”（纯换行符变化），属正常；构建用 LF 即可。
